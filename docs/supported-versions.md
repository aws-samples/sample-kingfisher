# Kingfisher Supported Versions

Scope: every runtime, AWS service engine, data-source driver and build-tool version that the Kingfisher platform depends on, as pinned in this repository.

**How to use this page**

- This page is the single source of versions; diagrams under `docs/diagrams/` never carry version numbers.
- Values are what the repository pins at the current commit, not what a given AWS account happens to run.
- To change a version, edit the code listed in Appendix A, update the row here and add a line under `[Unreleased]` in `CHANGELOG.md`, all in one commit.
- Supported means the combination passed the full headless-browser acceptance round before the release tag was cut; status words are defined in section 12.1.

Last updated: 2026-11-04 (platform `VERSION` 2.1.2; 2.2.0 candidate on the development branch).

## 12. Version and support policy

Platform versions follow Semantic Versioning. From 2.2.0 the release tag is `v<major>.<minor>.<patch>`, cut by `scripts/cut-release.sh`.
The tag, the `VERSION` file and the CHANGELOG heading must match.

### 12.1 Status values

| Status | Meaning |
|---|---|
| Supported | Pinned in the repository and exercised by acceptance |
| Default | Chosen when the user does not pick a value |
| Minimum | Lowest version accepted for the stated use |
| Legacy | Superseded, still recognised, not the upgrade target |
| Not pinned | The repository does not fix this value |
| Not supported | The platform does not offer this combination |
| Preview | Candidate not yet tagged, not for production |

### 12.2 Release rules

| Topic | Rule | Notes |
|---|---|---|
| Version scheme | SemVer `v<major>.<minor>.<patch>` | From 2.2.0 |
| Release branch | `release/<version>` | Cut from `main` |
| Release tool | `scripts/cut-release.sh <version> --yes` | Dry run without `--yes` |
| Hotfix | Patch plus 1 on `release/<version>` | Cherry-picked back to `main`, no `-bNNN` suffix |
| Historical tags | `release-<date>` and `release-<date>-<fix>` | 8 tags, still recognised, `v` tags win |
| Tag consistency | Tag, `VERSION` and CHANGELOG heading equal | Checked by the release tool |
| Release gate | Full headless acceptance round, zero reds | Stamp `.claude/mr-gate-stamp.json` |
| Running version | Login footer, Settings, `GET /api/public/version` | Baked at image build from git facts |
| Lockfiles | `npm ci` only | Developer machines, CI and CodeBuild |
| Upgrade notes | `docs/CUSTOMER-PROD-DEPLOY.md` and CHANGELOG | This page lists target versions only |

### 12.3 Deployment-time overrides

Overrides change one environment, not the supported matrix; a value used in production must be added to this page before it counts as supported.

| Override | Sets | Default | Notes |
|---|---|---|---|
| `-c flink-runtime=<id>` | `FLINK_RUNTIME_ENVIRONMENT` | `FLINK-1_20` | One environment only |
| `-c emr-release=<label>` | `EMR_RELEASE_LABEL` | `emr-spark-8.0.0` | One environment only |
| Env `DMS_ENGINE_VERSION` | DMS engine version | 3.5.4 | One environment only |
| Env `DMS_INSTANCE_CLASS` | DMS instance class | `dms.t3.small` | One environment only |
| Env `BEDROCK_MODEL_ID` | Deploy-time default model | Factory default | Runtime setting takes precedence |
