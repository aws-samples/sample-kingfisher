# Execution Role Binding · User-selectable Job Execution Roles (requirements + design)

> Revision **1.2** (2026-11-03).
> Status: ✅ **fixed and verified** (two product commits on 2026-11-03;
> all six gates green: tsc · vitest 5,761 tests · naming-parity · synth gate (including the new check 9.4d) · redline scan · IAM call manifest 142 entries;
> the new page-driven acceptance segment for execution-role binding passed **7/7** in a two-region demo test account in observe data-plane credential mode, and the contract-guard baseline taken before the change re-verified with 0 FAIL (28 pages / 7 contracts;
> the 6 WARNs are all body-length data drift on Home · Audit Log · FinOps · Task Monitor · Ops Dashboard · Settings, not contract regressions), see section 8).
> Revision 1.1: code written, awaiting verification.
> Decided on 2026-11-03: this is a **basic capability**; it must be fixed at the root and built to the highest global standard (same batch: [chaining sync tasks and batch jobs into one DAG published completely to Airflow Serverless](./workflow-job-node.md)).
> Origin: a customer production environment (release 2.1.2) moved the dependency libraries of a Batch Compute job to **its own S3 bucket** and wanted to bind the job to **an IAM role it had created itself**; the page would not accept the binding. After the job fell back to the platform role, Glue was denied with 403 while downloading `--extra-py-files` at launch (`LAUNCH ERROR … Error downloading from S3 … Forbidden`). Decided on 2026-11-03: **parity with AWS — every job can specify its own role; the roles the platform generates by default remain usable; the dropdown can be refreshed within the page; customers must be allowed to switch to their own buckets, so binding self-created roles must be allowed. Fix it at the root, keep it friendly, keep it compatible.**

## 1. Current state and root cause (🔵 code facts; the production tag `release-2026-10-29` and the development trunk are the same here)

| Layer | Fact | Consequence |
|---|---|---|
| Pages | Batch Compute (Glue / EMR), Data Sync and Stream Compute — four places in all — each have a **free-text** "Execution Role ARN" field whose help text promises "or enter a custom least-privilege role"; the role advisor's one-click creation writes back `bgp-job-role-*` | Users assume any role can be entered |
| Platform task role | `iam:PassRole` in `infra/lib/platform-stack.ts` allows only three classes: fixed platform roles (`bgp-glue-role` and the like) · the per-region `BgpExecEnv-*-<kind>-role` · the role advisor's `bgp-job-role-*` (with `iam:PassedToService`) | Any name the customer created ⇒ PassRole denied at Glue CreateJob / UpdateJob, EMR StartJobRun and Flink CreateApplication ⇒ **"cannot bind a role I created myself"** |
| Execution-region platform Glue role | `infra/lib/exec-env/core-stack.ts`: S3 access is deliberately limited to the region's two buckets, datalake and scripts ("no arbitrary user S3 buckets") | After falling back to the platform role, reading the customer bucket ⇒ **403** at launch |
| Preflight | `lib/role-advisor/preflight.ts` is called only on the EMR submit path; it measures only the engine baseline (log group / scripts bucket / data-lake bucket), not the external S3 URIs the job references; it does not check the trust policy | Save succeeds, the run blows up, and the raw error text does not point to the fix |
| No single author | The ARN regex and the "custom first, empty falls back" rule are each written once more in `lib/etl/job-service.ts` · `lib/sync/start-run.ts` · `lib/realtime/flink-service.ts` · `lib/engines/emr/{provider,schedule-fanout}.ts` | Fix one place, miss three |

In one sentence: **the UI claimed a capability that had no carrier** (the engineering rule that every capability the UI claims must have a carrier); the missing carriers are the IAM pass-role surface + a candidate source + a save-time preflight.

## 2. Requirements (contract)

| # | Requirement | Acceptance (page-driven) |
|---|---|---|
| R1 | All four job kinds (Batch Compute Glue job / Batch Compute EMR Serverless job / Data Sync Glue job / Stream Compute Flink application) can bind **any IAM role in the account that the service can assume** (the same rule as the "IAM role" dropdown in the AWS console); the platform default roles and the roles generated by the role advisor remain selectable as before. DMS / Redshift COPY roles are internal platform orchestration roles and are out of scope for this change | A self-created role (trusting glue.amazonaws.com) bound to a Glue job ⇒ save ⇒ run ⇒ the Glue job definition's Role = that ARN ⇒ the run succeeds |
| R2 | "Execution Role" changes from free text to a **dropdown** in three groups — platform default (for that region) / created by the role advisor (`bgp-job-role-*`) / your own (everything else); shows role names, searchable; plus an "Enter ARN manually" fallback | A role you just created shows up in the dropdown; the groups and counts match IAM |
| R3 | A "Refresh" button to the right of the dropdown re-fetches the candidates **without leaving the page** | Create a role in IAM → click Refresh → the dropdown shows it |
| R4 | The binding really works: the platform task role can pass any role in the account to glue / emr-serverless / kinesisanalytics (the `iam:PassedToService` condition locks the services); it can ListRoles / GetRole / SimulatePrincipalPolicy on any role | Same as R1; the synth gate asserts that the statement exists and carries the service condition |
| R5 | **Preflight moves forward to save time** (measured at save / start for all four job kinds): ① ARN shape ② the role exists ③ the trust policy contains the engine's service principal ④ permissions simulated against the job's **actual reference surface** — engine baseline + scripts bucket + every `--extra-py-files` / `--extra-jars` URI + every `s3://` literal appearing in the script ⑤ three states (complete / gaps / unverifiable).<br>Gaps ⇒ save / start is **rejected on the spot with 400**, listing each item as "action → resource → why it is needed" + the way out (grant these entries to the role / let the role advisor fill them in with one click / move the dependency libraries into the platform bucket through the page upload / leave the field empty to use the platform default) | A self-created role without GetObject on its own bucket ⇒ save rejected, the error names that bucket's ARN and `s3:GetObject`; after the permission is granted, save passes |
| R6 | Compatibility: the field name `executionRoleArn` (ETL `glueConfig` / EMR `spec` / sync `glueConfig` / Flink job) is **unchanged**; empty = platform default; existing values keep working; old clients that send an ARN directly keep working (they go through the same preflight); new endpoints are additive only. Upgrade = `redeploy-platform.sh` rolls the platform stack (task-role policy); execution regions need no redeployment; no new tables | An existing job saved without changes writes back the unchanged default; old ARN values stay as they are |
| R7 | Multi-region: the platform default entry follows the place (home = env such as `GLUE_ROLE_ARN`; non-home = `BgpExecEnv-<slug>-*`); self-created roles are account-global; the preflight simulation carries `aws:RequestedRegion = <that region>` (so a customer role with region conditions is measured correctly too); a job bound to several regions is measured region by region | Binding a self-created role from the us-west-2 view ⇒ the preflight uses the us-west-2 context |
| R8 | Friendliness: role names rather than ARNs; the group title states "Platform default (recommended, permissions complete)"; a one-line hint next to your own roles says "must trust <service principal> and be able to read the bucket holding the job's dependencies"; the preflight result is shown in place (✅ complete / ❌ N gaps / ⚠️ could not verify) | The headless checks read the text |

## 3. Design

### 3.1 IAM (`infra/lib/platform-stack.ts`, new ManagedPolicy `ExecutionRoleBinding` attached to the TaskRole)
```
PassRole   role/*   Condition StringEquals iam:PassedToService ∈ { glue.amazonaws.com, emr-serverless.amazonaws.com, kinesisanalytics.amazonaws.com }
ListRoles  *
GetRole / SimulatePrincipalPolicy   role/*
```
- No `aws:RequestedRegion` (IAM is global; adding it would block legitimate calls instead). No tag condition: decided on 2026-11-03 as "parity with AWS"; the security boundary = the service condition (the platform can hand a role only to these three services, the same rule as a console user who holds `iam:PassRole` + a service condition); **dms is not included** (users do not choose DMS roles).
- The three existing PassRole statements are **kept as they are** (behavior preserved; synth-gate check 9.4b untouched); new check 9.4d: a `role/*` PassRole must exist and **must** carry PassedToService, with the service set being exactly the three above; no `role/*` PassRole statement may lack a service condition.
- The IAM call manifest registers 6 entries (ListRoles / GetRole / SimulatePrincipalPolicy / PassRole × 3 services); the simulation gate measures the TaskRole against the manifest for real.

### 3.2 Platform-side single author `platform/src/lib/execution-role/`
| File | Responsibility |
|---|---|
| `types.ts` | `ExecRoleEngine = "glue" \| "emr" \| "flink"` (closed list); `SERVICE_PRINCIPAL_BY_ENGINE`; candidate / preflight types |
| `resolve.ts` | `assertRoleArnShape(arn)` (the only regex) · `resolveExecutionRoleArn({ custom, fallback, what })` (custom first, empty falls back, neither ⇒ throws the same message). The four entry points import it and delete their own regex / fallback copies (ratchet: the `iam::\d{12}:role` regex may appear in source only in this file) |
| `candidates.ts` | `listExecutionRoleCandidates({ engine, targetId })`: control-plane IAM `ListRoles`, paginated, full list → parse `AssumeRolePolicyDocument` (URL-encoded JSON) → roles whose `Principal.Service` contains the engine's principal are admitted → grouped as `platform` (= the default role ARN resolved for that place) / `advisor` (`bgp-job-role-*`) / `custom` (everything else);<br>internal platform roles (`BgpExecEnv-*` roles of other engine kinds, `bgp-*` internal orchestration roles) are **not listed**.<br>Returns `{ arn, name, kind, trusts: true, createDate, description }` + `fetchedAt` |
| `s3-uris.ts` | `s3UrisFromGlueConfig(cfg)`: splits extraPyFiles / extraJars on commas + validates `s3://bucket/key`; `s3UrisFromScript(code)`: reuses the S3 signals of `role-advisor/script-scan`. Pure functions |
| `preflight.ts` | `preflightExecutionRole({ engine, roleArn, targetId, scriptBucket, logBucket, extraS3Uris, scriptCode })` = calls the extended version of `role-advisor/preflight.preflightRole` (see 3.3) and returns the same `PreflightResult`;<br>also provides `preflightErrorResponse(result)` ⇒ `apiError(message, 400, { code: "EXEC_ROLE_PREFLIGHT_FAILED", detail: { gaps, roleArn, engine } })` |

### 3.3 Preflight extension (`lib/role-advisor/preflight.ts`, two additions inside the same author)
- `requireTrust`: after GetRole, parse the trust policy; if `Principal.Service` does not contain the engine's principal ⇒ `ok=false` + the message "This role does not trust glue.amazonaws.com, so Glue cannot assume it; in IAM, change the trusted entity to …".
- `extraS3Uris[]`: each URI appends two probes, `s3:GetObject → arn:aws:s3:::bucket/key` and `s3:ListBucket → arn:aws:s3:::bucket`, sid `JobDependencyRead`, why "job dependency library / script reference; Glue downloads it with the execution role at launch; if it cannot be read, the result is LAUNCH ERROR 403".
- `ContextEntries`: `aws:RequestedRegion = <place region>`.
- The three-state semantics are unchanged; `unverifiable` still does not block but is echoed back.

### 3.4 Endpoints
| Route | Description |
|---|---|
| `GET /api/exec-roles/candidates?engine=&targetId=` | Sign-in required; engine not in the closed list / missing targetId ⇒ 400 (the place is explicit; the home region is never assumed); returns `{ groups: { platform[], advisor[], custom[] }, servicePrincipal, fetchedAt }` |
| `POST /api/exec-roles/preflight` | body `{ engine, targetId, roleArn, extraS3Uris?, scriptCode? }` ⇒ `PreflightResult`; used by the page's "Check permissions" button; the save path measures again on the server by itself (it does not trust the client) |

### 3.5 Wiring (four entry points + two save points)
| Where | Change |
|---|---|
| `lib/etl/job-service.ts#ensureGlueJob` | Takes the role through `resolveExecutionRoleArn`; for a custom role, `preflightExecutionRole` (extra = the two glueConfig fields + the script scan) ⇒ gaps ⇒ throws `ExecRolePreflightError` (the route maps it to 400) |
| `app/api/etl-jobs/route.ts` POST · `[id]/route.ts` PUT | When the body carries a non-empty `glueConfig.executionRoleArn` and the job type is glue ⇒ preflight each bound target before saving; gaps ⇒ 400, nothing is written |
| `lib/sync/start-run.ts` | Same, `ensureReject(400, …)` |
| `lib/realtime/flink-service.ts` | Same (engine flink, extra = none; trust principal kinesisanalytics) |
| `lib/engines/emr/provider.ts` · `schedule-fanout.ts` | Already has a preflight; switched to the single author; the fan-out gains the preflight |

### 3.6 Page: `components/exec-roles/ExecutionRolePicker.tsx` (reused in four places)
- props: `engine` · `targetIds` (takes the first / gives every one of them the platform default entry of the candidate intersection) · `value` · `onChange(arn | "")` · `isAdmin` · `extraS3Uris?` · `scriptCode?`.
- Structure: `Select` (showSearch, `optionGroups` in three groups, first entry "Platform default role (recommended)" with value `""`) + a "Refresh" button (`data-testid=exec-role-refresh`, re-fetches the candidates and reports "Refreshed: N roles available") + an "Enter ARN manually" toggle (switches to an Input; compatibility per R6) + a "Check permissions" button (calls the preflight endpoint; result as a Tag: complete / N gaps (expandable list) / could not verify).
- The role advisor `RoleAdvisorPanel` stays beneath it; `onFilled` ⇒ sets the value + triggers a refresh, so the newly created advisor role appears in the "Created by Role Advisor" group immediately.
- Text (zh / en in the same commit into `messages/en.ts`): "Your own role must trust {service}; this role must be able to read the buckets referenced by the job's dependency libraries / script".
- Replacement points: `app/etl-jobs/page.tsx` (glue) · `components/engines/EmrJobPanel.tsx` · `app/sync/SyncTaskModal.tsx` (controlled Form.Item) · `app/realtime-compute/page.tsx`.

## 6. Risks
- `ListRoles` is slow in accounts with many roles (> 1000): paginated 100 at a time, full list; the result carries `fetchedAt`; the page fetches only on open / refresh.
- Customer roles with conditions such as `aws:RequestedRegion`: the preflight measures with the region context; whatever cannot be measured is reported honestly as `unverifiable`.
- PassRole widened to `role/*`: the boundary = the three service principals; stated in the documentation; if a security review needs to narrow it, a tag condition can be added on top (left open, not in this change).
